# Project Context

**Name:** LocalLoop (formerly Ghost-Link)
**Description:** A cross-platform trust and approval layer for AI coding agents. 

## Current Milestone
**Mobile UI Redesign for Approval-First Flow**
Following the successful integration of the Claude Code hook prototype, our focus is now on redesigning the mobile app. We are moving from a passive "terminal observation" layout to a notification-driven, "Face ID approval" inbox interface.

## Strategic Vision
LocalLoop serves as the "Face ID for AI agents." As agents become more autonomous, the bottleneck shifts from code generation to trust and execution safety. LocalLoop intercepts high-risk agent operations (via native hooks like Claude Code's `PreToolUse` or MCP) and pushes an approval request to the developer's mobile device for biometric authorization.

## Core Value Proposition
- **Agent Trust:** Safely leave autonomous agents unattended.
- **Cross-Platform:** A lightweight background daemon (macOS/Linux/Windows) integrating with any agent standard.
- **Low Friction:** Push notification → glance → Face ID approve → agent continues. 

## High-Level Architecture
1. **Cross-Platform Daemon:** Hosts integration endpoints (e.g., HTTP listener for Claude Code hooks) and an E2EE relay connection.
2. **E2EE Relay:** Facilitates internet-routed NAT traversal without inspecting payloads.
3. **Mobile Client (Flutter):** Actionable inbox for notifications, risk policy engine, and Ed25519 signature generator.

## Key Terminology
- **Hook Payload:** The structured request sent by an agent (like Claude Code) attempting to execute a tool.
- **SignedEnvelope:** The Ed25519 cryptographic signature generated by the mobile app to prove human authorization.
