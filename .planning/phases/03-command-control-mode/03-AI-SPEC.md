## 1. System Classification

**System Type:** Extraction / Natural Language Understanding

**Description:**
The Command Composer takes unstructured natural language input (e.g. "Kill the dev server and restart it") from the Flutter mobile app and processes it into a strict, structured JSON intent representing the action to be taken on the Windows workstation. It also classifies the risk level of the intent so the policy engine can require approval.

**Critical Failure Modes:**
1. **Hallucinated destructive actions:** Outputting an intent to delete files when the user asked to read them.
2. **Missing parameters:** Failing to extract the target process name or ID when the user says "kill node".
3. **Improper risk classification:** Classifying a high-risk action (e.g. "format C:") as low-risk, bypassing the approval engine.

## 1b. Domain Context

**Industry Vertical:** Developer Tooling / System Administration

**User Population:** Software developers monitoring their workstations remotely via mobile.

**Stakes Level:** High (Commands execute on the user's primary development machine with their user privileges).

**Output Consequence:** Output intents are passed directly to a policy engine, which then executes them or prompts for manual approval on the mobile device.

### What Domain Experts Evaluate Against

- **Intent Accuracy:** Does the structured output exactly match the user's explicit request without assuming unstated parameters? (Good: Explicitly mapped / Bad: Assumed defaults for dangerous parameters).
- **Risk Classification:** Is the command correctly identified according to the principle of least privilege and maximum safety? (Good: Errs on the side of caution / Bad: Fails open).

### Known Failure Modes in This Domain
- **Over-eager interpretation:** Interpreting "What is the docker process doing?" as a command to interact with the docker process rather than just read its logs.
- **Ambiguity resolution:** The LLM guessing the target rather than asking for clarification when multiple targets exist.

### Regulatory / Compliance Context
None strictly apply, but system integrity and security best practices for local remote-execution engines apply.

### Domain Expert Roles for Evaluation

| Role | Responsibility |
|------|---------------|
| Senior Developer | Reviewing test cases for destructive edge cases and ambiguous commands. |

## 2. Framework Decision

**Selected Framework:** Microsoft.SemanticKernel

**Version:** 1.14.x

**Rationale:**
Since the policy engine and event store are running in a C# .NET 8 Worker Service, Semantic Kernel provides a robust, native C# abstraction for interacting with LLMs, generating structured data, and managing prompts.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| Raw HTTP calls to Gemini API | Lacks built-in prompt templating and retry/resilience policies. |
| LangChain.NET | Less native support from Microsoft compared to Semantic Kernel. |

**Vendor Lock-In Accepted:** Partial — Semantic Kernel abstractions make it easy to swap models later if needed.

## 3. Framework Quick Reference

### Installation
```bash
dotnet add package Microsoft.SemanticKernel
```

### Core Imports
```csharp
using Microsoft.SemanticKernel;
using Microsoft.SemanticKernel.ChatCompletion;
```

### Entry Point Pattern
```csharp
var builder = Kernel.CreateBuilder();
builder.AddOpenAIChatCompletion("model-name", "api-key");
var kernel = builder.Build();

var prompt = @"Parse the following command into JSON matching the schema: {{$command}}";
var result = await kernel.InvokePromptAsync(prompt, new() { ["command"] = "stop the build" });
```

### Common Pitfalls
1. Failing to configure structured JSON output properly in the execution settings, leading to markdown-wrapped JSON (` ```json `).
2. Not handling token limit exceptions on massive terminal logs.

## 4b. AI Systems Best Practices

### Structured Outputs with Pydantic / C# Records

Use C# Records for the expected JSON structure and utilize the model's JSON mode or structured output features.

```csharp
public record CommandIntent(
    string Action,
    string Target,
    Dictionary<string, string> Parameters,
    string RiskLevel, // Low, Medium, High
    string Explanation
);
```

### Async-First Design
Ensure all kernel invocations are fully async and handle cancellation tokens gracefully, especially since this runs in a background worker service that might be stopped.

### Prompt Engineering Discipline
Use a strong System Prompt defining the exact allowed actions, target types, and risk matrices. Do not allow the LLM to invent new action verbs.
